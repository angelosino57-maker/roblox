# P1: Höhlen – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Fünf gemeinsame Biom-Höhlen aus Terrain mit Bereichen und Deko, Tore aus jedem Schacht, Eier liegen in den Höhlen und werden selbst aufgehoben (nur für den eigenen Spieler sichtbar), Biom-Atmosphäre.

**Spec:** `docs/superpowers/specs/2026-09-29-hoehlen-umbau-design.md` (Abschnitte 2, 3, 7).

**Architecture:** Reine Logik `Config/Biomes`, `ShaftLayout` (Plots/Tore), `EggSpawner` (aktive Anker, Nachwachsen), `Migrate` (Profil v1→v2), `Genetics.hatch` pro Biom – getestet. Editor-Builder `CaveBuilder` (Terrain + Deko + Anker, deterministisch) wird einmal per MCP ausgeführt. Server `CaveEggService`, Client `CaveEggController` + `AmbienceController`. `ShaftService`-Wände bekommen Tore.

## Global Constraints

- Biome/Schichten/Zonen/Materialien/Arten/Gene/Brutzeiten exakt wie Spec-Tabellen. Pflicht-Spitzhacke: jungle 1, ice 2, volcano 2, crystal 4, eldorado 4.
- Höhlenfläche x, z ∈ [−200, 200]; Schacht-Säulen (56×56 inkl. Wände) bleiben terrainfrei.
- Tor: Wand Richtung Kartenmitte, Zellen 5–6 entlang der Wand, Schichten `toLayer-2 … toLayer`.
- 6 aktive Eier pro Spieler und Biom, Nachwachsen 60 s an einem anderen Anker, Aufheben ≤ 12 Studs, Taste E.
- Ei-Daten `{id, biome, rarity, foundAt}`; Profil `version = 2` mit Migration (earth→jungle, stone→ice, crystal→crystal; Minenlore→Enterhaken wird in P2 genutzt, Migration setzt sie schon jetzt um).
- Keine Ei-Blöcke mehr.

### Task 1: Reine Logik

- `Config/Biomes`: `list`, `byId`, `forLayer(layer) -> biome?`, `topY(biome)`, `floorY(biome)`; Felder `id, name, eggName, fromLayer, toLayer, requiredTier, species, geneRange, hatchSeconds, minRarity?, ambience = {ambient, fogColor, fogEnd}`.
- `ShaftLayout`: `CELL = 96`, `PLOT_COUNT = 8`, `plotCenter(i)`, `shaftOrigin(i)`, `gateWall(i) -> "N"|"S"|"E"|"W"`, `isGateOpening(i, x, layer, z) -> boolean` (Zelle außerhalb des 12×12-Rasters direkt hinter der Torwand), `gateCells(i, biome) -> {{x, layer, z}}` (die 6 Zellen im Schacht an der Torwand), `gateWorldPosition(i, biome) -> Vector3` (Mitte der Toröffnung auf Bodenhöhe, außen vor der Wand). `WorldBuilder` nutzt `ShaftLayout` für die Plot-Mitten.
- `EggSpawner`: `new() -> state {active = {[spot] = true}, pending = {{readyAt, exclude}}}`, `fill(state, spots: {string}, now, rng, max) -> changed: boolean`, `pickup(state, spot, now, delay) -> boolean`.
- `Eggs.entries(minRarity?)` (ersetzt `DailyService.eggEntries`), `Eggs.name(biomeId)`.
- `Genetics.hatch(egg, rng, id)`: Art aus `Biomes.byId[egg.biome].species`, Gene aus `geneRange`.
- `Migrate.run(data)`: v1→v2 (Eier/Brutplätze bleiben gültig, `zone` → `biome`; `owned.up.minecart`/`equipped.up == "minecart"` → `grapple`), setzt `version = 2`, idempotent.
- Tests: `Biomes.spec`, `ShaftLayout.spec`, `EggSpawner.spec`, `Migrate.spec`; `Genetics.spec` auf Biome umgestellt (Gene-Bereich, Arten nur aus Biom-Liste).
- [ ] Tests schreiben → LOAD FAIL → implementieren → `0 failed` → Commit `feat: Biome, Schacht-Layout, Ei-Spawner, Migration`.

### Task 2: Schacht ohne Ei-Blöcke, mit Toren

- `ShaftGen.kind` liefert nie mehr `"egg"` (Zonen-`eggChance` entfernt); Tests angepasst.
- `ShaftService`: Wände werden in Segmente zerlegt, sodass an jeder Torstelle ein Loch ist; `isOpen` behandelt Tor-Öffnungen als offen; beim Aufbau werden die Tor-Zellen aller Biome gerendert; Egg-Item-Pfad entfernt.
- Alle `egg.zone`-Nutzer auf `egg.biome` (BackpackService, HatchService, DailyService/Config.Daily, CreaturePanel, WorkshopPanel, TradePanel). `DataService` ruft `Migrate.run` nach `Reconcile`.
- Prüfung per DevBridge: Tor-Zellen existieren als Parts; Wand-Segmente haben Lücken; alle Tests grün. Commit `feat: Schacht-Tore zu den Biom-Höhlen, keine Ei-Blöcke mehr`.

### Task 3: CaveBuilder (Editor)

- `src/server/CaveBuilder.luau`: `CaveBuilder.build(biomeId)` / `buildAll()`: Hülle aus Fels füllen, organische Hallen per `FillBall`/`FillBlock` (Air) aus festem Seed, Boden-Schicht im Biom-Material, Schacht-Säulen freiräumen, Tunnel von jedem Tor Richtung Mitte, drei Bereiche je Biom (Spec-Tabelle) mit Deko-Parts in `workspace.Caves.<biom>.Decor` und Ei-Ankern in `workspace.Caves.<biom>.EggAnchors` (30–40 Anker; Boden per Raycast, Baumkronen/Nester an Deko-Punkten).
- Einmal im Editor ausführen, je Biom Screenshot; nachbessern bis begehbar und stimmig.
- Commit `feat: fünf Biom-Höhlen (Terrain, Bereiche, Deko, Ei-Anker)`.

### Task 4: Eier aufheben

- Remotes `CaveEggs` (Server→Client `{[biomeId] = {spot}}`), `PickupEgg(spot)`.
- `CaveEggService`: Anker beim Start aus `workspace.Caves` lesen; pro Spieler/Biom `EggSpawner`; 1-s-Loop `fill`; `pickup` mit Prüfungen (Anker aktiv, Abstand, Spitzhacken-Stufe `"tier"`, Rucksack `"full"`) → Seltenheit mit Glück → `BackpackService.add` → Notify → Snapshot.
- `CaveEggController`: Ei-Modelle (Farbe je Biom, leichtes Funkeln) + ProximityPrompt „Aufheben“ (E) an aktiven Ankern; entfernt aufgehobene.
- Prüfung: DevBridge `pickup` mit Spieler am Anker → Ei im Rucksack; zu weit → `"far"`; nach `fill(now+61)` wieder 6 aktiv; Screenshot mit Ei in der Höhle.
- Commit `feat: Eier in den Höhlen aufheben`.
